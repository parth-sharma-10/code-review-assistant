# Setup

Tested on macOS 26 with Node.js 24.19, npm 11 and Docker Desktop. Linux is expected to work the same
way. Windows was not tested.

## 1. Prerequisites

| Tool | Version | Check |
|---|---|---|
| Node.js | 20 or newer | `node -v` |
| npm | 10 or newer | `npm -v` |
| Docker (with Compose) | any recent | `docker compose version` |
| OpenSSL | any | `openssl version` (only used to generate secrets) |

## 2. Install dependencies

```bash
git clone <repo-url> code-review-assistant
cd code-review-assistant
npm install
```

This is an npm workspace (`backend/`, `frontend/`), so one install covers both.

**npm 11 blocks install scripts by default.** The four packages that need them are pre-approved in the
root `package.json` (`allowScripts`): `argon2` (native binding), `prisma`, `@prisma/engines` and
`@prisma/client`. npm also lists `fsevents`, `unrs-resolver` and `@parcel/watcher` as
"not yet covered by allowScripts": those are optional tooling scripts, and lint, test and build pass
without them (verified from a fresh clone). If npm warns about the four required packages, run:

```bash
npm approve-scripts argon2 prisma @prisma/engines @prisma/client && npm rebuild argon2 prisma @prisma/engines
```

## 3. Start PostgreSQL

```bash
docker compose up -d postgres
docker compose ps          # wait for "healthy"
```

Postgres 16 listens on **localhost:5433** (not 5432, so it cannot collide with a locally installed
Postgres). On first start, `backend/prisma/init/01-test-db.sql` also creates
`code_review_assistant_test`, the database the integration tests use.

## 4. Configure the backend

```bash
cp .env.example backend/.env
openssl rand -hex 32    # paste as JWT_SECRET
openssl rand -hex 32    # paste as ENCRYPTION_KEY
```

The backend validates its environment at startup and prints every invalid variable if something is
wrong. `backend/.env` is git-ignored.

Optional: set `OPENAI_BASE_URL` / `OPENAI_API_KEY` / `OPENAI_MODEL` to give every user a fallback
provider. Most people configure providers in the UI instead.

## 5. Create the schema

```bash
npm run prisma:deploy -w backend      # applies prisma/migrations to the dev database
```

The Prisma client is generated by the backend's `postinstall` script during `npm install`;
`npm exec -w backend -- prisma generate` regenerates it after a schema change.

## 6. Run

Two terminals:

```bash
npm run dev:backend      # NestJS on http://localhost:4000 (watch mode)
npm run dev:frontend     # Next.js on http://localhost:3000
```

Open http://localhost:3000. The frontend proxies `/api/*` to the backend, so you only ever use port 3000.

Production-style run:

```bash
npm run build                              # set BACKEND_URL first if the API is not on :4000
npm run start -w backend &                 # node dist/main
npm run start -w frontend                  # next start on :3000
```

`BACKEND_URL` is compiled into the frontend build (Next.js rewrites are resolved by `next build`).
Changing it later requires rebuilding the frontend; setting it only for `next start` has no effect.

## 7. Configure an AI provider

Go to **AI providers → Add provider** and pick a preset. The free, local option:

```bash
brew install ollama          # or see https://ollama.com/download
ollama serve                 # if it is not already running as a service
ollama pull qwen2.5-coder:7b # ~4.7 GB; runs on a machine with 16 GB+ RAM
```

Choose the **Ollama** preset (base URL `http://localhost:11434/v1`, model `qwen2.5-coder:7b`, no key),
save, then click **Test connection**.

LM Studio: load a model, start the server (Developer → Start server), use the **LM Studio** preset with
the model identifier LM Studio shows, and set the model's context length to at least 16k.

## 8. Tests, lint, build

```bash
npm test              # needs the Postgres container running
npm run lint
npm run format:check
npm run build
```

## Troubleshooting

| Symptom | Cause / fix |
|---|---|
| `Invalid environment configuration: JWT_SECRET ...` on startup | `backend/.env` missing or a secret is empty or too short. Repeat step 4. |
| `Can't reach database server at localhost:5433` | Container not running: `docker compose up -d postgres`. |
| Integration tests fail with `database "code_review_assistant_test" does not exist` | The Postgres volume was created before the init script existed. Run `docker exec cra-postgres psql -U cra -d code_review_assistant -c 'CREATE DATABASE code_review_assistant_test'`. |
| `Error: Cannot find module ... argon2` | The native build was skipped. See the npm 11 note in step 2. |
| Review fails with "did not match the required format after 2 attempts" | The model could not produce valid JSON twice. Retry, or use a larger model. |
| Review fails with "did not respond within 180s" | The local model is too slow for the request. Review fewer files, or raise `AI_TIMEOUT_MS`. |
| Review fails with "Could not reach the AI provider" | Wrong base URL, or the model server is not running. Use **Test connection**. |
